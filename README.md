# GXヒーロー診断アプリ

真庭市GXイベント向けの子供向けアンケート（ゲーム版・イベント中用）。
20問の5段階診断に答えると、5カテゴリの得点からオリジナルヒーロータイプが表示される。

仕様の詳細は [`仕様書_GXヒーロー診断アプリ.md`](../仕様書_GXヒーロー診断アプリ.md) を参照。

## セットアップ

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 起動

```
uvicorn app.main:app --reload
```

`http://127.0.0.1:8000/` にアクセス。回答データは `data/app.db`（SQLite）に保存される。

## 管理画面

`http://127.0.0.1:8000/admin` で回答一覧・CSVダウンロード・QRコード発行が可能。
パスワードは環境変数 `ADMIN_PASSWORD` で設定（未設定時は開発用デフォルト `maniwa-gx-admin`。本番投入前に必ず変更すること）。

セッション署名用の `SECRET_KEY` も本番環境では環境変数で必ず上書きすること。安全な値は以下で生成できる。

```
python -c "import secrets; print(secrets.token_hex(32))"
```

### QRコード発行

管理画面にURL入力欄がある。デプロイ後の本番URLを入力すると、その場でQRコード画像（PNG）を生成できる。画像を保存してチラシ等に印刷する。

## デプロイ：2パターン（当日の保険として両方用意）

### パターン1：会場Wi-Fi版（ローカルサーバー）

会場に持ち込んだPCでサーバーを起動し、参加者は同じWi-Fiに繋いでアクセスする方式。インターネット接続・クラウドアカウント一切不要。

**事前準備（1回だけ・管理者権限のPowerShellで実行）**

Windowsファイアウォールは既定でこのアプリへの外部端末からの接続をブロックする（特にWi-Fiが「パブリックネットワーク」扱いの場合）。事前に許可ルールを追加しておくこと。

```
New-NetFirewallRule -DisplayName "GX Hero App" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

**当日の起動**

```
.\scripts\start_local_event.ps1
```

- 管理画面パスワードと、参加者に案内すべきURL候補（このPCのローカルIPアドレス）が表示される
- 表示されたURLのうち、会場Wi-Fiのアダプタに対応するものを選び、`/admin` のQRコード発行機能でQR化して掲示する
- 会場Wi-Fiルーターの同時接続台数の上限に注意（[同時接続について](#同時接続について)を参照）。100人規模を想定する場合は業務用アクセスポイントを推奨
- PCの電源を挿しっぱなしにし、スリープ・画面ロックを無効化しておくこと

### パターン2：Render版（GitHub連携）

インターネット経由でどこからでもアクセスできるクラウド版。GitHubリポジトリと連携し、Web画面の操作だけでデプロイできる（CLI・クラウドアカウントのコマンド操作は不要）。

**事前準備（あなたの操作が必要）**

1. [GitHub](https://github.com/) でアカウントを作成し、新しい空のリポジトリを作成する
2. このフォルダ（`gx_hero_app`）で以下を実行し、作成したリポジトリにpushする（`<URL>` は作成したリポジトリのURLに置き換え）

   ```
   git remote add origin <URL>
   git push -u origin main
   ```

3. [Render](https://render.com/) でアカウントを作成する（GitHubアカウントでのサインアップ可）
4. Renderのダッシュボードで **New +** → **Blueprint** → 先ほどのGitHubリポジトリを選択
   - リポジトリ内の `render.yaml` を自動検出し、Dockerfileベースでビルド・デプロイされる
   - `ADMIN_PASSWORD` / `SECRET_KEY` は自動生成される（デプロイ後、Renderダッシュボードの環境変数タブで実際の値を確認できる）
5. デプロイ完了後に発行されるURL（`https://xxxx.onrender.com`）を、`/admin` のQRコード発行機能でQR化する

**注意点**

- 無料プランはアクセスが一定時間無いとスリープし、次回アクセス時に起動まで数十秒かかることがある（イベント当日の待ち時間になり得る）
- 無料プランは永続ディスクが使えないため、**再起動・再デプロイのたびにそれまでの回答データ（SQLite）が消える**。本番の予備系として実データを保存し続けたい場合はStarterプラン以上＋ディスク追加（`render.yaml`にコメントアウトで記載済み）を検討すること
- パターン1（会場Wi-Fi版）をメインとし、パターン2は「Wi-Fiが不調な場合の予備」「会場外からの動作確認用」として使い分けるのがおすすめ

### （参考）その他のクラウド環境でのDocker起動

Cloud Run / ECS / Azure Container Apps など、コンテナ実行可能な環境であれば同じ`Dockerfile`でそのままデプロイできる。

```
docker build -t gx-hero-app .
docker run -p 8080:8080 -e ADMIN_PASSWORD=xxxx -e SECRET_KEY=xxxx gx-hero-app
```

**注意：** SQLite (`data/app.db`) はコンテナ内のローカルファイルに保存される。コンテナは再起動・スケールアウトでファイルが消えたり複数インスタンス間で共有されなかったりするため、複数インスタンスで運用する場合は永続ボリュームのマウント、またはCloud SQL等の外部DBへの切り替えを検討すること。

## 同時接続について

最大同時接続100人を想定して以下の対応を行い、実際に100人同時アクセスをシミュレートして検証済み（成功率100/100、全員が回答完了まで平均7秒弱）。

- SQLiteをWALモードに変更（`app/db.py`）し、書き込み中も他の接続が待たされにくいようにした
- FastAPIの内部スレッドプール上限をデフォルト40→150に引き上げ（`app/main.py`の起動処理）

負荷検証は `scripts/load_test.py`（Python版）でも実行できるが、環境によってはローカルのファイアウォール／セキュリティソフトがPythonプロセスからのループバック接続をブロックすることがある（本検証機ではこれが発生したため、PowerShellの`Invoke-WebRequest`ベースで代替検証を行った）。実行できない場合はセキュリティソフトの除外設定を確認すること。

**なお、アプリ自体のボトルネックは小さいことを確認済みだが、実運用では会場のWi-Fi機器側が先に限界を迎える可能性が高い。** 100人同時接続を安定して捌くには、家庭用ルーターではなく業務用アクセスポイント（同時クライアント数100以上を公称するもの）の使用を推奨する。
